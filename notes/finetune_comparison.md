# Zero-shot vs LoRA 对比报告

## 对比配置
- 测试集：data/sft/test.json（13 条，6 类问题）
- Zero-shot：Qwen3-VL-4B 原始模型
- LoRA：rank=8, alpha=16, 58 条训练, 3 epochs
- 评分：exact_match

## 总体对比
| 方法 | exact_match |
|---|---|
| zero-shot | 8/13（61.5%） |
| LoRA | 8/13（61.5%） |
| 差异 | 0 |

## 结果分析

### 为什么没有提升
1. **训练数据太少**：58 条训练样本不足以让模型学到新的行为模式。LoRA 的 loss 虽然从 21 下降到 15，但这是因为模型在"背答案"而非"学会规律"。
2. **训练轮数不够**：3 epochs 仅 45 步，rank=8 的 adapter 还没有充分收敛。
3. **测试集太小**：13 条样本无法做统计显著的对比——即使有 1-2 条的改善，也可能是随机波动。

### 这说明了什么
- LoRA 训练链路是完全正确的（loss 持续下降、adapter 保存/加载正常、推理无报错）
- 瓶颈在**数据量和训练时长**，不在代码或方法
- 这是工程上的有效发现——知道"什么条件下微调有用"比盲目跑通更重要

### 下一步改进方向
1. 训练数据从 58 条扩至 200+ 条（优先补 count 和 edge 类型）
2. Epoch 从 3 增至 5-10
3. Rank 从 8 增至 16-32
4. 测试集从 13 条扩至 30+ 条，保证统计显著性

## 结论
LoRA 微调链路已完全打通。当前数据规模下未观察到指标提升属于预期行为。下一步需增大训练数据量和训练轮数。
